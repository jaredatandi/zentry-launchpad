# Zentry Launchpad — v1 MVP

A free-stack client portal and launch-page factory for **Zentry** (Nairobi software
engineering and cybersecurity business owned by Jared Atandi). The service lines
are **software development** — web apps, Android and iOS mobile apps, desktop apps
for Windows, macOS and Linux, APIs, cloud and CI/CD — and **cybersecurity** —
secure code review, threat modelling, vulnerability assessment and remediation,
DevSecOps, and authorised testing inside written scope. The US$79 launch page is
the fixed-price entry point, not the whole business.

> Guard the entry. Move at speed.

It turns an enquiry into a client, generates the **US$79 / KES 2,500 one-page
holding site** (tap-to-call, address, three-field enquiry form, two revisions,
48-hour delivery), stores the generated HTML, serves it at `/p/:slug`, and brings
enquiries back into the owner's admin inbox. It also produces print-ready
invoices with the correct payment rails.

## What is included

- **Public site**: marketing home, `/holding-page` SEO guide, `/demo` live example,
  `/launch-page` offer and `/contact` lead form (honeypot + in-memory rate limit).
- **Owner admin**: single account, bcrypt hash, signed HTTP-only cookie. Dashboard
  with counts and source/conversion stats, lead pipeline
  (`new → qualified → quoted → paid → in_production → delivered → lost`), client
  records, invoice generator, enquiry inbox, activity log.
- **Page generator**: escaped, mobile-first static HTML generated from client
  intake (business name, phone, address, service blurb, accent colour). Stored in
  SQLite, exported to `generated/<slug>.html`, served at `/p/:slug`.
- **Invoices**: US$79 or KES 2,500 as applicable; Kenya shows M-Pesa Till `6200945`
  with the client's phone as reference; international says "bank details are sent
  on confirmation". Two revision rounds and 48h delivery printed on every invoice.

### Hard rules in this codebase

- Budget is **exactly $0**. No paid tiers, trials, cards, subscriptions, ads or
  billed API keys. See [DEPENDENCIES.md](DEPENDENCIES.md).
- No third-party payment wallets or overstated global-coverage claims in customer-facing copy.
- No security-testing, scanning or exploit features. Any testing happens only

## $0 local run

Requirements: Node.js 20+ and npm (both free/open source). On Windows, a free C++
build toolchain may be needed for `better-sqlite3` if no prebuilt binary exists.

```bash
# 1. Install everything (one time)
npm install

# 2. Create .env from the example, then set the owner password
cp .env.example .env
npm run setup:admin -- jaredkeago07@gmail.com 'choose-a-long-password'

# 3. Create the SQLite database and demo seed (one time)
npm run db:init

# 4. Run both servers in two terminals
npm run dev:api     # http://localhost:3001
npm run dev:web     # http://localhost:5173
```

Open `http://localhost:5173` for the public site and
`http://localhost:5173/admin/login` for the owner admin. Vite proxies `/api` to
the backend in development.

`npm run db:init` seeds one clearly fictional demo lead, client, page, enquiry and
invoice. To start clean, delete `backend/data/zentry.db*` and run it again.

### Tests and production build

```bash
npm test                # validation, auth and page-generation tests
npm run build           # compiles backend and builds frontend/dist
npm start               # serves API, generated pages and frontend on :3001
```

## Environment variables (`.env`, gitignored)

| Variable | Purpose | Example |
| --- | --- | --- |
| `PORT` | Backend port | `3001` |
| `DB_PATH` | SQLite file, relative to project root | `./backend/data/zentry.db` |
| `SESSION_SECRET` | Random string used to sign the session cookie | `openssl rand -hex 32` |
| `ADMIN_EMAIL` | Single owner login email | `jaredkeago07@gmail.com` |
| `ADMIN_PASSWORD_HASH` | bcrypt hash (never a plain password) | generated by `setup:admin` |
| `COOKIE_SECURE` | `true` only over HTTPS | `false` locally, `true` behind TLS |
| `TRUST_PROXY` | Hop count for a known reverse proxy; leave blank otherwise | `1` |
| `VITE_API_BASE_URL` | Frontend API base; empty uses same origin/proxy | `https://your-free-tunnel.example` |
| `GENERATED_DIR` | Optional export directory override (tests use a temp folder) | `./generated` |

`npm run setup:admin -- <email> '<password>'` writes `ADMIN_EMAIL`,
`ADMIN_PASSWORD_HASH` and a strong random `SESSION_SECRET` into `.env`. The app
refuses to start in production without all three. Leave `TRUST_PROXY` blank when
the app is directly exposed so `X-Forwarded-For` cannot spoof rate-limit keys.

### Security posture

- Single-account auth: bcrypt cost 12, HS256 signed JWT in an HTTP-only,
  `SameSite=Lax` cookie; sign-out revokes the token server-side.
- Failed sign-in is rate-limited to 5 attempts per 15 minutes per IP + account.
- Public forms use a honeypot, minimum fill time and per-IP rate limits.
- Zod validates every input; all generated HTML is escaped; SQL is parameterised.
- Security headers (CSP, nosniff, frame/Permissions-Policy, HSTS over TLS) are set
  by Express. Generated pages use first-party inline script/style only.

## Deploy (still $0, no card)

The production stack is **Vercel Hobby (free) + Turso SQLite (free)**: the React
site and the Express API share one `*.vercel.app` origin, and data lives in a
remote SQLite database. Both providers offer a genuine no-card free tier and
GitHub sign-in.

1. Create a free Turso database: `turso db create zentry-launchpad`.
2. Copy the schema in with
   `turso db shell zentry-launchpad < backend/migrations/001_initial.sql`.
3. Create a token: `turso db tokens create zentry-launchpad`.
4. In Vercel, import `jaredatandi/zentry-launchpad` and add these Environment
   Variables: `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `SESSION_SECRET`,
   `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH`, `COOKIE_SECURE=true`, `TRUST_PROXY=1`.
   Generate the secret and bcrypt hash locally with `npm run setup:admin`, then
   paste only their values into Vercel — never into git.
5. Deploy. `vercel.json` builds both workspaces, serves `frontend/dist` and
   routes `/api/*` and `/p/*` to the single serverless function in `api/index.js`.

For local development, leave the Turso variables empty: `npm start` uses the
gitignored SQLite file in `backend/data` and Vite proxies `/api` to port 3001.
Never commit bank details, tokens, `.env` or the SQLite file.

The pre-existing free assets remain reachable and are referenced by the new site:
the [original site](https://jaredatandi.github.io/zentry-site/),
the [holding-page guide](https://jaredatandi.github.io/zentry-site/holding-page.html)
and the [live demo](https://jaredatandi.github.io/zentry-site/example.html).

## API outline

Public: `POST /api/leads`, `POST /api/enquiries`, `GET /p/:slug`.

Owner-only (signed HTTP-only cookie required): `POST /api/admin/login`,
`POST /api/admin/logout`, `GET /api/admin/dashboard`, `GET/PATCH
/api/admin/leads[/:id]`, `GET/POST/PATCH /api/admin/clients[/:id]`,
`POST /api/admin/pages/generate`, `GET /api/admin/pages/:id/html`,
`GET/PATCH /api/admin/pages/:id`, `POST/GET /api/admin/invoices[/:id]`,
`GET/PATCH /api/admin/enquiries[/:id]`, `GET /api/admin/activity`.

All inputs are validated with zod; client text is HTML-escaped before it enters
a generated page or invoice. Public forms use a honeypot, a minimum fill time and
a fixed-window rate limit.
